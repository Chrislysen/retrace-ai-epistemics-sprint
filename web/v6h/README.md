# RETRACE four-state source-review workbench

Run from the repository root with `python -m retrace.server_v6h --port 8769`, then open `http://127.0.0.1:8769/lab`. This separate loopback server does not alter the older workbenches and makes no model calls. `python -m unittest tests.test_workbench_v6h -q` runs the offline backend and HTTP checks; `node --check web/v6h/app.js` checks JavaScript syntax.

Load the constructed demo, or import a JSON bundle containing `source_documents`, `registry`, and `source_ir`. Optional fields are `id`, `title`, `documents` (document-to-evidence veto groups), `clarifications`, `target_decisions`, and `allowed_withdrawals`. The two editors separate the source bundle from its proposed IR. Preparing a source prompt is a local export, not an inference request.

Analysis distinguishes supported, not supported, contested, and insufficient provenance. Disagreement between supplied readings is separate from conflict between positive and negative warrants within a reading. Source spans establish locations, not textual entailment. Source completeness and real-world truth remain unknown. Missing registered identifier dispositions withhold current decisions until the interpretation explicitly classifies them as operational or nonoperational.

The demo is outside the study corpus. Its eight constructed readings include a scoped exception with a protected alternative, an explicit negative warrant, an unidentified ancestry gate, an inactive prerequisite, and a three-record withdrawal. The first decision-relevant question concerns the negative warrant; the unused-record question is unnecessary for current decisions. Applying the three-record withdrawal makes a previously irrelevant route question matter. No hidden reference graph or preferred actual reading is supplied.

Answers filter the supplied choice family. Unknown retains readings. The minimax plan assumes accurate available binary answers and minimizes declared worst-case question cost until current four-state decision vectors agree. It does not estimate probabilities or expected value of information; agreement can still leave contested arguments or insufficient provenance. Source, IR, or other declaration edits invalidate prior statuses and start a fresh answer/veto state. The API requires the current declaration fingerprint for nonempty state.

Document, passage, and scenario vetoes are independent. Clearing one never clears another, changes an original inactive flag, or removes a copy-parent requirement. Withdrawal witnesses count record IDs, not independent causes. Hypothetical enable-then-withdraw diagnostics are previews and cannot be applied as actual restoration. Exact-search bounds return an explicit unavailable result rather than a partial result.

Counter-reading previews accept the same envelope as the v6h refuter prompt: `status`, `ir`, `objection_spans`, and `warning_score`. Every cited span and all IR branches must validate before comparison. A valid proposal is evaluated as an addition to the current family, never automatically applied or treated as source truth. Reset Boolean clarification answers before comparing new choice structures; answers cannot silently transfer to another interpretation. Warning scores remain raw and uncalibrated. An abstention does not certify completeness. The workbench exports bundles and analyses on request and does not persist them automatically.

The server exposes only the local v6h demo, source preparation, analysis, and refuter-preview endpoints. It rejects foreign origins, nonlocal hosts, duplicate/nonfinite JSON, unknown body fields, and oversized bodies. Local users can review sensitive text without sending it elsewhere; sharing prepared source text with an external model is a separate user action.
